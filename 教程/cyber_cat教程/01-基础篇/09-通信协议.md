## 1.9.1 RESTful API 设计

### REST 原则

**REST 是什么？** REST（Representational State Transfer）是一种架构风格，核心原则：

1. **客户端 - 服务器分离**：前端和后端独立开发
2. **无状态**：每个请求包含所有必要信息
3. **可缓存**：响应可以缓存
4. **统一接口**：使用标准 HTTP 方法
5. **分层系统**：可以有中间层（代理、网关）

### 资源命名规范

```
# 好的设计（名词，复数）
GET    /users           # 获取用户列表
GET    /users/123       # 获取 ID=123 的用户
POST   /users           # 创建新用户
PUT    /users/123       # 更新用户 123
PATCH  /users/123       # 部分更新用户 123
DELETE /users/123       # 删除用户 123

# 嵌套资源
GET    /users/123/orders      # 获取用户 123 的订单
GET    /users/123/orders/456  # 获取订单 456

# 动作资源（用 POST）
POST   /users/123/avatar      # 上传头像
POST   /orders/456/cancel     # 取消订单
```

### 响应格式设计

```json
// 成功响应
{
    "code": 200,
    "data": {
        "id": 123,
        "name": "Alice"
    },

{

    "message": "缺少必填字段：name",
    "details": {
        "field": "name",

// 分页响应
{
    "data": [...],
    "pagination": {
        "page": 1,
        "size": 20,
        "total": 150
    }
}
```

## 1.9.2 JSON 数据格式

### JSON 基础

**JSON 是什么？** JSON（JavaScript Object Notation）是一种轻量级数据交换格式。

```json
{
    "字符串": "hello",
    "数字": 42,
    "浮点数": 3.14,
    "布尔值": true,
    "null": null,
    "数组": [1, 2, 3],
    "对象": {
        "嵌套": "value"
    }
}
```

### Python 中的 JSON 处理

```python
import json

# 字典转 JSON 字符串
data = {
    "name": "Cyber Cat",
    "age": 3,
    "skills": ["STT", "LLM", "TTS"]
}
json_str = json.dumps(data, ensure_ascii=False)
print(json_str)
# {"name": "Cyber Cat", "age": 3, "skills": ["STT", "LLM", "TTS"]}

# JSON 字符串转字典
data = json.loads(json_str)
print(data["name"])  # Cyber Cat

# 读写 JSON 文件
with open("data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

with open("data.json", "r", encoding="utf-8") as f:
    data = json.load(f)
```

### FastAPI 中的 JSON

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

# 定义请求/响应模型
class ChatRequest(BaseModel):
    text: str
    session_id: str | None = None

class ChatResponse(BaseModel):
    reply: str
    emotion: str
    audio_url: str

@app.post("/chat", response_model=ChatResponse)
async def chat(req: ChatRequest):
    # FastAPI 自动将 dict 转为 JSON
    return {
        "reply": "喵~",
        "emotion": "happy",
        "audio_url": "http://server/tts/xxx.wav"
    }
```

```cpp

}
```

## 1.9.3 HTTPS 与证书

### HTTP vs HTTPS

```
HTTP:  明文传输，容易被窃听和篡改
HTTPS: HTTP + SSL/TLS 加密，安全

HTTP  端口：80
HTTPS 端口：443
```

### SSL/TLS 工作原理

```
客户端                          服务器
  |                              |
  |-------- Client Hello --------|
  |                              |
  |<------- Server Hello --------|
  |<------- 服务器证书 -----------|
  |                              |
  |---- 验证证书，生成密钥 -------|
  |                              |
  |-------- 加密密钥交换 -------->|
  |                              |
  |<------- 握手完成 -----------|
  |                              |
  |====== 加密通信 =============|
```

### 证书类型

| 类型 | 说明 | 成本 |
|------|------|------|
| DV（域名验证） | 验证域名所有权 | 免费（Let's Encrypt）|
| OV（组织验证） | 验证组织信息 | 付费 |
| EV（扩展验证） | 严格验证，浏览器显示绿锁 | 付费 |

### ESP32 上的 HTTPS

```cpp
#include <WiFiClientSecure.h>

// 方式 1：跳过证书验证（开发环境）
WiFiClientSecure client;
client.setInsecure();  // 不验证证书

// 方式 2：使用根证书（生产环境）
const char* root_ca = \
    "-----BEGIN CERTIFICATE-----\n" \
    "MIIE...（证书内容）" \
    "-----END CERTIFICATE-----\n";

client.setCACert(root_ca);

// HTTPS 请求
if (client.connect("api.example.com", 443)) {
    client.println("POST /chat HTTP/1.1");
    client.println("Host: api.example.com");
    client.println("Content-Type: audio/wav");
    client.println();
    // 发送数据...
}
```

### 自签名证书（开发测试）


## 1.9.4 音频编码基础

### 数字音频参数

| 参数 | 说明 | 本项目值 |
|------|------|---------|
| 采样率 | 每秒采样次数 | 16kHz |
| 位深 | 每个样本的位数 | 16-bit |
| 声道数 | 单声道/立体声 | 单声道 |
| 比特率 | 每秒数据量 | 256kbps (16k×16×1) |

### WAV 文件格式

```
WAV 文件结构：

偏移     大小     名称              说明
0x00     4        RIFF ID           "RIFF"
0x04     4        RIFF Size         文件总大小 -8
0x08     4        WAVE ID           "WAVE"
0x0C     4        fmt ID            "fmt "
0x10     4        fmt Size          16 (PCM)
0x14     2        Format Tag        1 (PCM)
0x16     2        Channels          1 (单声道)
0x18     4        Sample Rate       16000
0x1C     4        Byte Rate         32000 (16k×16×1/8)
0x20     2        Block Align       2 (16×1/8)
0x22     4        Bits Per Sample   16
0x26     4        data ID           "data"
0x2A     4        data Size         PCM 数据大小
0x2E            PCM Data           音频数据
```

### 设备端生成 WAV 头

```cpp
// 生成 44 字节 WAV 头
struct WavHeader {
    char riff[4] = "RIFF";
    uint32_t riffSize;
    char wave[4] = "WAVE";
    char fmt[4] = "fmt ";
    uint32_t fmtSize = 16;
    uint16_t audioFormat = 1;  // PCM
    uint16_t numChannels = 1;  // 单声道
    uint32_t sampleRate = 16000;
    uint32_t byteRate = 32000; // 16000 * 16/8 * 1
    uint16_t blockAlign = 2;   // 16/8 * 1
    uint16_t bitsPerSample = 16;
    char data[4] = "data";
    uint32_t dataSize;
};

// 填充头
void createWavHeader(WavHeader* h, uint32_t pcmSize) {
    h->riffSize = pcmSize + 36;  // 36 = 44 - 8
    h->dataSize = pcmSize;
}

// 使用
WavHeader header;
createWavHeader(&header, pcmDataSize);

// 发送：header + PCM 数据
client.write((uint8_t*)&header, sizeof(header));
client.write(pcmData, pcmDataSize);
```

### PCM 数据格式

```cpp
// 16-bit PCM 数据
// 单声道：连续的 16 位样本
// 立体声：交错的 L-R-L-R...

int16_t samples[] = {100, -200, 300, -400, ...};

// 读取样本值（范围：-32768 到 32767）
int16_t sample = samples[i];

// 归一化到 -1.0 到 1.0
float normalized = sample / 32768.0f;

// 音量调整
float volume = 0.5f;  // 50% 音量
int16_t adjusted = (int16_t)(sample * volume);
```

### 音频数据处理流程

```
ESP32 录音流程：

麦克风 → I2S ADC → PCM 数据 → 添加 WAV 头 → HTTP POST → 后端

后端 STT 流程：

WAV 数据 → SiliconFlow API → JSON{transcript} → 提取文字

后端 TTS 流程：

文字 → SiliconFlow API → WAV 数据 → HTTP 返回 → ESP32 → I2S DAC → 喇叭
```

## 常见问题

**Q: HTTPS 和 HTTP 性能差距大吗？**  
A: 现代硬件上差距很小（<5%）。主要开销在握手阶段，长连接可忽略。

**Q: WAV 和 MP3 有什么区别？**  
A: WAV 是无损格式，文件大；MP3 是有损压缩，文件小。本项目用 WAV 因为 ESP32 处理能力有限。

**Q: JSON 解析失败怎么办？**  
A: 检查 JSON 格式是否合法（引号、逗号），编码是否为 UTF-8，使用在线 JSON 验证工具。
